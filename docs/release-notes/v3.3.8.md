# v3.3.8 — 单模型收敛：思考交给 `.env`，并修复多轮失忆与非流式丢内容

> 上游已把「快速模式 / 专家模式」合并（`client/settings?scope=model` 里 `expert` 是 `enabled:false, switchable:false`，请求体里的 `model_type` 一律被改写回 `"default"`）。本版据此把模型面收敛为**一个模型**，把「是否思考」交回 `.env`，同时修掉两个会让客户端"看起来变傻"的缺陷。

## 变更重点

### 1. 只有一个模型

- `/v1/models` 现在**只返回一个** id：`MODEL_NAME`（默认 `deepseek-chat`）。
- **是否输出推理链由 `.env` 的 `THINKING` 决定**（`auto` / `enabled` / `disabled`），而不是切换模型名。请求级仍可用 `thinking_mode` 覆盖（服务端 `THINKING=enabled|disabled` 时以服务端为准）。
- 老名字（`deepseek-reasoner`、`deepseek-r1`、`deepseek-thinking`、`deepseek-expert` 等）**继续被接受**，写入 SDK 的旧调用不会 404——但它们现在只是别名，**不再改变行为**，也不会出现在 `/v1/models` 里。
- `MODEL_ROUTES` 从默认配置降级为**可选高级覆盖**：不配置即为单模型；确需按模型名分流时才配置（配置后 `/v1/models` 列出它的键）。`.env.example` 中的默认 `MODEL_ROUTES` 已移除并改为注释说明。

### 2. 修复多轮对话失忆

客户端如果**每轮只发最新一条消息**（历史不构成上一轮的前缀延伸），旧版会判定"历史发散"、丢弃上游会话并新建，于是模型每轮都从零开始——问「我叫什么名字」答不上来。

- 现在发散时**保留会话与 `parent_message_id` 链，改为重发完整 prompt**；历史一致延伸时仍只发新增尾部（保留原有的省 token / 防静音收益）。
- 发散次数记录在 `ChatSession.diverged_turns`，并输出 `session_prompt_diverged` INFO 日志，便于观察某个客户端是否长期处于发散态。
- 顺带修复：流式与非流式原先使用 `stream:` / `nonstream:` 两套会话缓存键，同一对话切换 `stream` 会各建一个会话（同样的失忆症状）。现在共用同一 `conv:<sha256>` 命名空间。

### 3. 修复非流式丢内容（两处）

- **丢答案**：开启思考时，短答案可能整段装在引入 RESPONSE 片段的那一帧里（例如 `1+1=?` → `content:"2"`，之后没有 token）。非流式解析器此前只切换片段类型、丢弃该帧内容，导致 `content` 为空。现已计入正文。
- **丢推理链**：非流式路径把 `adapter` 返回的 thinking 取了却从未写进响应体，因此 `thinking_mode=true` + `stream=false` 拿不到 `reasoning_content`（同一 prompt 走流式却有 100+ 字）。现在 `thinking` 非空时补 `reasoning_content`，为空时不加该键——与流式路径的字段名完全一致。

### 4. 其它

- 管理接口返回的服务版本号修正为当前版本（此前停留在 `3.3.6`）。
- `/admin/api/env` 的 `session_cache_ttl` 回落值与真实默认值对齐（600 → 1800）。
- FastAPI 元信息由 `DeepSeek Chat API (Expert Preview)` / `2.2.0` 更正为 `DeepSeek Chat API` / 当前版本。
- WebUI Playground：模型下拉只标注「deepseek-chat（唯一模型）」，选择模型不再联动思考开关；思考开关与「联网搜索」开关就是仅有的两个能力控制，文案同步说明「只有一个模型，是否思考由开关或服务端 `THINKING` 决定」。

## 升级提醒

1. **想要推理链的用户**：请设 `THINKING=enabled`（或客户端传 `thinking_mode: true`）。本版**不再**因为模型名写着 `deepseek-reasoner` 就自动开启思考。
2. **写死两个模型名的客户端**：建议改为只请求 `MODEL_NAME`；旧名仍可用但语义已收敛，未来可能移除。
3. **配置了 `MODEL_ROUTES` 的用户**：配置仍然生效（按模型名给 thinking/search 预设），但它是可选项，删掉即回到"单模型 + `THINKING`"的默认行为。旧简写 `"expert"` / `"quick"` 仍被识别为 thinking 开/关。
4. **旧 `MODE`**：`expert` ≡ `THINKING=enabled`，`quick` ≡ `THINKING=disabled`，`auto` 不介入；已废弃，仅保证旧 `.env` 继续可用。
